PC Supporter 규칙 엔진: 모르면 모른다고 답하기

호환성 규칙 엔진이 판정 근거와 정보 부족을 어떻게 결과에 담는지, 실제 코드와 검증 결과로 설명합니다.

PC Supporter는 다나와 부품 카탈로그로 PC 견적의 호환성을 검사하는 서비스입니다. 맞다, 틀리다만 알려 주면 믿고 사기 어려워서, 판정마다 근거를 붙이는 구조로 만들었습니다. 개발 문서의 첫 원칙도 “호환성 판정과 데이터 신뢰도·가격·실제 조립 검증을 한 상태로 뭉개지 않습니다”입니다. 엔진은 shared/domain/engine.ts에 있습니다.

무엇을 시도했나

규칙은 결과를 finding으로 남깁니다. 규칙 ID, 심각도, 영향받는 부품, 판정 사실, 사용자가 할 수 있는 행동이 함께 들어갑니다. 심각도는 blocker, warning, info, unknown으로 나눕니다. 정보가 없을 때 쓰는 addUnknown은 누락된 필드를 판정 사실로 넣고, 스펙을 확인하라는 행동을 붙입니다.

완전 호환 판정은 unknown까지 없어야 나옵니다.

function isFullyCompatible(blockerCount: number, warningCount: number, unknownCount: number) {
  return blockerCount === 0 && warningCount === 0 && unknownCount === 0;
}

물리값이나 제조사 근거가 없으면 자동 통과로 올리지 않습니다. KBO Fans 위젯에서 모르는 값을 0으로 채우지 않은 판단과 같습니다.

어디서 막혔고 어떻게 판단을 바꿨나

엔진을 믿을 수 있는지부터 확인하려고 10월 2일에 배포 카탈로그에서 무작위 부품셋 300건을 돌렸습니다. 실행 오류, 결과 일관성 위반, 독립 판정과의 불일치는 0건이었습니다. 하지만 NVMe SSD를 장착 불가로 잘못 막는 사례처럼 문제는 다른 곳에서 나왔습니다. 문서의 결론은 이렇습니다.

남은 문제는 파서와 데이터 쪽입니다

엔진이 unknown을 정직하게 내면 데이터가 비었을 때 unknown이 많아집니다. 그래서 규칙을 느슨하게 하지 않고 데이터를 메우기로 했습니다.

무작위 300건으로 엔진 점검파서와 데이터 문제 분리제조사 원문으로 케이스 사양 보강장착 조건을 판정에 추가

10월 4일 작업에서는 파서를 고치고 제조사 원문으로 케이스 사양을 보강했습니다.

케이스 사양 보강 전 보강 후
위치별 라디에이터 지원 0/56 51/56
지원 PSU 규격 51/56 53/56
SSD 베이 1/56 56/56

장착 조건도 판정에 넣었습니다. 검증에서 H6 Flow의 27mm 라디에이터는 후면 I/O 설치 조건이 확인되지 않아 unknown, 31mm는 제조사 한도 30mm를 넘어서 blocker가 나왔습니다.

배운 것

규칙 엔진의 정확도와 사용자가 받는 답의 품질은 다른 문제였습니다. 엔진이 전부 맞아도 입력이 비면 답은 “확인 필요”뿐입니다. 그래서 문제가 나올 때 엔진, 파서, 데이터 가운데 어디인지 먼저 나눠 적습니다. 며칠 뒤 슬롯 일에서 쓴 서버, 표시, 빌드를 나눠 보는 습관과 같은 구조입니다.

위 표에 비어 있는 케이스가 남아 있습니다. 운영 데이터베이스에는 아직 반영하지 않았습니다. 메인보드 전원부 규칙은 추정 계수의 근거가 약해 이틀 뒤 판정 방식을 바꿨습니다.

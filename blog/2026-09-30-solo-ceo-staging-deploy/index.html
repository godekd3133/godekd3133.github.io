작업일지: 솔로사장 스테이징 배포

개인정보 요청 범위를 정리하고 GCP 단일 VM에 스테이징 백엔드를 올린 날입니다. 외부 연동은 대역으로 두었고 서비스는 미출시입니다.

솔로사장은 수업 사업계획서에서 출발한 소상공인 지원금·세무 준비 백오피스입니다. 이 날은 스테이징 백엔드를 GCP에 올렸습니다. 아직 출시한 서비스는 아닙니다.

한 일

개인정보 관련 작업을 먼저 끝냈습니다. 요청 범위가 잘못되면 거부하게 고치고, 내보내기를 범위별로 나누고, API 의존성을 잠그고 런타임 이미지를 감사하도록 빌드를 바꿨습니다. 그다음 Compute Engine VM 한 대에 스테이징 전체를 올렸습니다.

필요한 것 스테이징에서 쓴 것
TLS와 진입점 Caddy
대기열 ElasticMQ (SQS FIFO 호환)
파일 저장 S3 호환 저장소
알림, 사업자 조회, 악성 파일 검사, 결제 검증 표준 라이브러리로 만든 대역 서버

막힌 것

운영 역할 점검이 실패했습니다. 원인은 PostgreSQL 초기화 스크립트였습니다. 런타임 search_path를 %L 문자열 형식으로 넣었더니 pg_catalog, public 전체가 스키마 이름 하나로 저장되어 current_schemas(false)가 비었습니다. 식별자 목록으로 설정하도록 고쳤습니다.

판단

  • 대역이 실제 연동처럼 보이지 않게 경계를 나눴습니다. 악성 파일 대역은 EICAR 표시만 찾고, 사업자 대역은 번호 체크섬만 계산합니다. 영수증 검증은 실제 스토어가 없으므로 항상 verified=false입니다.
  • 실제 결제사 연동은 미뤘습니다. 운영 설정에서 결제 백엔드를 끄면 런타임 결제 시도는 거절됩니다.
  • 파일럿 공고 수집은 소스 하나로 시작하고, 나머지는 파일럿 뒤에 평가하기로 했습니다.
대역이 답하는 것

형식과 체크섬, 표시 여부까지입니다.

답하지 않는 것

실제 결제, 실제 사업자 상태, 실제 악성 파일 여부입니다.

다음에 할 것

스테이징은 출시가 아닙니다. 실제 결제사, 스토어 결제, 법률 검토, 외부 API 계약이 남아 있습니다. 대신 신고해 주는 서비스가 아니라 자료 수집과 내보내기까지만 제공한다는 범위도 그대로입니다. 이 글의 대역 경계는 다음 글의 규칙 엔진에서 판정 결과의 경계로 다시 나옵니다.

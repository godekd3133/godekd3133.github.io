AI2026.11.02

AI 도구로 일하는 방식은 어떻게 바뀌었나

Codex와 Claude Code 사용 기록을 바탕으로 2025년 8월부터 지금까지를 다섯 단계로 나눴습니다.

제 Codex와 Claude Code 사용 기록과 당시 팀 채널에 적은 글을 돌아보며 정리했습니다. 2026년 7월 무렵부터 업무 전반을 AI에 맡기기 시작한 것이 가장 큰 전환점입니다. 단계마다 쓴 글을 링크로 이었습니다.

다섯 단계

시기 단계 무엇이 바뀌었나 자세한 글
2025.08 ~ 2026.02 탐색 도구를 시험해 보던 때입니다. 탐색
2026.03 ~ 06 업무 투입 스킬, 서브에이전트, MCP, 병렬 에이전트를 처음 썼습니다. 업무 투입
2026.07 ~ 08 대량 위임 업무 전반을 AI에 맡기고, 작업을 많은 세션으로 나눴습니다. 대량 위임
2026.09 검증 강화 수정 뒤 테스트와 빌드를 돌리는 비중이 크게 늘었습니다. 검증과 병행
2026.10 ~ 병행과 다수 제품 두 도구를 함께 쓰고, 개인 제품으로 개발 범위를 넓혔습니다. PC Supporter, 커리어센터

생각이 어떻게 옮겨 갔나

쓸 만한가어떻게 맥락을 남기나어떻게 팀이 같이 시작하나끝났다는 걸 어떻게 아나좋아졌다는 걸 어떻게 아나

처음의 질문은 실제 코드에 쓸 만한가였습니다. 2025년 여름의 제 메모는 프롬프트와 코드 인덱서가 있으면 개선할 수 있겠다는 것이었습니다. 그다음에는 CLAUDE.md와 컨텍스트 파일로 세션 사이에 맥락을 남기는 쪽으로 옮겨 갔습니다. 2026년 2월 보고서에 적은 패턴도 이것입니다.

반복해서 말하던 피드백은 스킬이 됐고, 터미널이 진입 장벽이 되자 GS App을 만들었습니다. 많이 맡기자 끝났다는 보고를 믿을 수 없어 Runtime Lab으로 화면까지 확인했고, 스킬이 좋아졌는지 말할 수 없어 벤치마크를 만들었습니다. 벤치마크에서는 다시 제 채점기부터 고쳐야 했습니다.

한 가지 문제와 조치

맡기는 양이 늘자 수정 뒤 검증을 빠뜨리는 일이 잦았습니다.

문제

에이전트의 완료 보고를 그대로 읽으면 실행하지 않은 부분이 빠집니다.

조치와 변화

완료 조건을 실행 결과로 바꾸고, 어디까지 실행해 확인했는지 나눠 보고합니다. Codex 수정 세션 중 검증 명령이 있는 비중이 8월 32%에서 9월 82%로 올랐습니다. 반복 자동화로 부풀었을 수 있어 방향으로만 봅니다.

제가 맡는 일

2026년 2월에도, 지금도 제 일은 비슷합니다. AI가 잘못된 가정으로 갈 때 교정하고, 기준을 정하고, 최종 확인을 합니다. 달라진 것은 그 기준을 대화가 아니라 스킬, 도구, 채점기에 남긴다는 점입니다.

다음에 할 것

아직 답하지 못한 것이 둘 있습니다. 스킬이 결과를 얼마나 바꾸는지는 본 실험을 보류했고, 팀 업무가 얼마나 빨라졌는지는 측정하지 않았습니다. 개인 제품은 대부분 실제 사용자 검증이 남았습니다. 다음 단계의 글은 이 셋 가운데 하나에 답하는 글이었으면 합니다.

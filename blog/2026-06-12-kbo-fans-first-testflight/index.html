작업일지: KBO Fans 첫 TestFlight

0.0.31부터 0.0.34까지 릴리즈를 정리한 날입니다. 푸시 배포 권한 오류를 넘겼지만 실기기 검증은 남았습니다.

위젯을 다듬은 뒤 첫 TestFlight 릴리즈 작업을 한 날입니다. 앞날인 6월 11일 작업까지 함께 적습니다.

그날의 맥락

기말 발표를 앞두고 테스터가 쓸 빌드가 필요했습니다. 앱은 직접 데이터 모드를 유지하되, 푸시와 Live Activity 토큰 등록만 배포한 백엔드로 보내는 구성이었습니다. 이 날 기록의 쟁점은 어디까지를 완료라고 적을지였습니다.

  • 6.11 푸시 백엔드 배포, 권한 오류를 차례로 해결
  • 6.12 0.0.31부터 0.0.34까지 릴리즈, 더미 토큰 스모크
  • 6.13 0.0.35, 0.0.36에서 푸시 초기화 보정, 토픽 재등록 경로 추가
  • 8.31 TestFlight 심사 승인

한 일

버전 내용
6.11 GitHub Actions로 푸시 백엔드를 AWS에 배포 시도
0.0.31 앱 종료 후에도 일반 푸시와 Live Activity를 갱신하는 경로, 배포 스크립트
0.0.32 마이팀 경기 시작 알림을 기본으로, 라이브 경기 감지 시 Live Activity 자동 추적
0.0.33 배포된 백엔드 주소를 빌드에 넣어 토큰 등록이 실제 서버로 가게 함, 업로드 확인
0.0.34 라인업 알림에서 경기 상세로 진입, 문자중계 오류 수정

막힌 것

6월 11일 CloudFormation 배포가 권한 때문에 계속 멈췄습니다. 서비스 연결 역할, ALB 보안그룹 조회, ECS 역할 정책 조회, EFS 네트워크 인터페이스 권한을 한 번에 하나씩 찾아 추가했습니다. 찾기 쉽도록 실패 이벤트 로그와 출력 범위부터 늘렸습니다. 마지막에는 EFS 레지스트리 잠금 오류도 고쳤습니다.

6월 12일에는 실기기 확인까지 가지 못했습니다.

판단

배포 권한 오류로그 범위부터 확대더미 토큰으로 스모크 확인실기기 푸시는 미완료로 표시
  • HTTPS 도메인을 연결하기 전에 스모크 검증부터 하려고, 해당 ALB 주소에만 iOS ATS HTTP 예외를 임시로 넣었습니다. 최종 운영 전에 없앨 항목입니다.
  • 실제 토큰 없이 확인할 수 있는 부분은 더미 토큰으로 등록과 해제를 해 보고, 끝난 뒤 지워졌는지 확인했습니다.
  • 실기기 확인을 못 했으므로 푸시 검증을 완료로 표시하지 않고 남은 작업으로 적었습니다.

마지막 항목은 이후 완료 조건을 실행 결과로 바꾼 일과 같은 방향입니다.

권한 오류를 나눠 본 기록

6월 11일에 막힌 권한은 네 종류였습니다.

막힌 곳 추가한 것
서비스 연결 역할 관련 권한
ALB 보안그룹 조회
ECS 역할 정책 조회
EFS 네트워크 인터페이스 권한

오류를 한 건씩 맞히는 방식은 느리지만, 무엇이 필요한지를 실패 이벤트로 확인하고 넣게 됩니다. 로그 범위를 먼저 넓힌 이유는 한 번 실패할 때 많이 알아내기 위해서입니다.

같은 날의 다른 작업에는 라인업 알림을 눌렀을 때 생기던 오류 경로 수정, 문자중계 표기 보정, 수업 발표 자료의 데이터 처리 설명 수정이 있습니다. 앱이 백엔드를 어디까지 쓰는지 발표 문구에서도 맞춰 적어야 했습니다. 다음 날 0.0.35와 0.0.36에서 다시 푸시를 고친 것을 보면, 이 날의 미완료 표시는 실제로 할 일이 남아 있었다는 뜻입니다. 푸시 토픽 재등록 경로도 그때 추가했습니다.

업로드에 쓴 빌드에는 토큰 등록용 백엔드 주소를 넣었고, 데이터는 직접 모드를 유지했습니다. 기능 전체를 백엔드로 옮기는 것보다 푸시 경로부터 분리해서 올린 판단입니다. 이렇게 하면 백엔드에 문제가 생겨도 경기 정보 표시가 함께 멈추지 않는다고 봤습니다. 이 효과는 장애 상황에서 시험하지 않았으므로 제 해석입니다. 비용 관리 문서와 배포 문서가 뒤에 더 생긴 것도, 이 날의 백엔드가 아직 임시 구성이었다는 것을 보여 줍니다.

정리하면 이 날의 결과는 업로드 성공과 서버 쪽 스모크 통과이고, 알림이 실제 기기에 닿는지는 그대로 다음 작업으로 넘어갔습니다. 작업 기록에도 실기기 검증 상태를 따로 남겼습니다.

판단 근거와 결과

0.0.34 기록에는 정적 분석과 Flutter 테스트 통과, TestFlight 업로드 성공, 아카이브 안의 버전 번호와 내장 패치 노트 확인이 남아 있습니다. 내보내기 중 dSYM 누락 경고도 함께 적었습니다.

검사 확인한 범위 확인하지 못한 범위
더미 토큰 스모크 등록, 해제, 삭제 확인 Apple 푸시 서버를 거친 실제 도달
업로드 빌드와 내장 설정 설치 후 알림 권한 흐름
앱 테스트 앱 코드 Dynamic Island 자동 시작

제 해석입니다. CloudFormation 권한을 한 번에 하나씩 찾는 데 시간이 걸린 것은 첫 배포의 필요 권한을 미리 정리하지 않았기 때문으로 보입니다. 반대로 처음부터 넓은 권한을 주면 빠르지만 줄이기 어렵습니다. 어느 쪽이 맞았는지는 비교하지 않았습니다. ATS 예외도 편의와 맞바꾼 임시 조치여서 남은 작업으로 표시했습니다.

다음에 할 것

TestFlight 설치 후 알림 권한, 실기기 푸시, Dynamic Island 자동 시작 확인과 HTTPS 전환이 이 날 남은 항목입니다. 8월 31일에 TestFlight 심사 승인을 받았습니다.

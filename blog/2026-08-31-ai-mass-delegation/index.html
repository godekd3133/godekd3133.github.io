대량 위임: 업무 전반을 AI에 맡기기 시작하다

2026년 7월 무렵부터 업무 전반을 AI에 맡기기 시작했고, 검증 누락이 드러나 완료 조건을 바꿨습니다.

(2026년에 돌아보며 쓴 글입니다.)

절차를 스킬로 옮긴 뒤, 2026년 7월 무렵부터 업무 전반을 AI에 맡기기 시작했습니다. 슬롯 개발을 돕는 사내 AI 도구를 만들기 시작한 것도 이 무렵입니다.

왜 시작했나

코딩 도구 밖의 일까지 맡기고 싶었습니다. 6월부터 슬랙에서 쓰는 개인 에이전트 AgentB를 시험해 스킬, 세션 이동 도구, 통화, 로컬 모델 연결을 차례로 시도했습니다. 다만 슬랙 안에서는 태그해야 움직인다는 플랫폼 제한이 가장 아쉬웠습니다.

무엇을 시도했나

작업을 많은 세션으로 나누고, 8월에는 자동 검토와 훅 설정도 쓰기 시작했습니다. 직접 코드를 치는 시간보다 작업을 나누고 결과를 확인하는 시간이 늘었습니다. 사용량을 아끼려고 단계마다 모델을 나누기도 했습니다. 9월에 팀에 공유한 슈퍼 보너스 사례가 이런 구성입니다.

단계 맡긴 일
서버 계획 모드로 구조 설계, 목표 모드로 개발과 시뮬레이션
클라이언트 구조 설계, 기존 작업 스타일에서 벗어나지 않도록 교정
흐름 시퀀스 위주 제작과 연출 위주 제작을 다른 모델에

어디서 막혔고 어떻게 바꿨나

많이 맡기자 수정 뒤 검증을 빠뜨리는 일이 잦았습니다. 에이전트는 끝났다고 보고하는데 실제로는 돌려 보지 않은 경우입니다. 그래서 완료 조건을 에이전트의 보고가 아니라 실제 실행 결과로 바꿨습니다.

이전

에이전트가 완료했다고 쓰면 다음 단계로 넘어갑니다.

이후

실행한 명령과 결과가 있어야 완료입니다. 어디까지 확인했는지 층별로 나눠 적습니다.

8월에는 제 피드백을 모아 회고했습니다. 후속 수정을 전부 에이전트 실수로 보지 않고 직접 오해, 사양 변경, 런타임에서 처음 드러난 결함, 증거 미완료로 나눴습니다. 이 분류는 스킬을 다시 정리한 글에 이어집니다.

많이 맡김검증 누락이 드러남완료 조건을 실행 결과로도구로 확인 범위를 넓힘

AgentB로는 7월에 직접 전화를 걸게 하는 도구와 로컬 모델을 Codex에 라우팅하는 방법을 시험했습니다. 앞의 표에서 클라이언트 구조를 설계한 뒤 기존 작업 스타일을 기준으로 한 번 더 교정하는 단계를 둔 것은 3월에 적은 코딩 스타일 피드백을 절차로 옮긴 것입니다.

사내 게임잼에서도 같은 방식을 썼습니다. 2026년 23월 AI 게임잼에서는 미니게임 허브와 코어 시스템, 에이전트 작업 규칙을 만들었고, 79월 신규 게임 탐색에서는 후보를 여럿 만들어 비교한 뒤 하나에 집중했습니다.

배운 것

위임이 늘수록 제 일은 코드를 치는 일에서 나누는 일과 확인하는 일로 옮겨 갔습니다. 그리고 AI 도구를 팀 전체가 쓰게 하려면 터미널 밖에 시작 지점이 따로 있어야 했습니다.

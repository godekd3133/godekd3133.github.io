KBO Fans

내 팀 경기를 위젯과 잠금 화면에서 바로 보는 야구 팬 앱

베타 (TestFlight), 서비스, 2026년 3월 ~ 10월

실행하기GitHub 저장소 열기

가상 선수와 합성 경기 데이터로 체험합니다. 실제 경기 기록이 아니며, 위젯은 설명용 미리보기입니다.

풀려던 문제

오늘 경기 스코어와 문자중계를 보려고 앱을 여러 번 열 필요가 없도록 위젯과 Live Activity에 모았습니다.

오늘 내 팀 경기 상황을 앱을 여러 번 열지 않고 바로 확인하고 싶은 KBO 야구 팬을 위한 앱입니다.

주요 기능

홈과 잠금 화면 위젯

내 팀 경기 상황을 홈 화면과 잠금 화면에서 크기별로 보여 줍니다.

Live Activity

iOS 잠금 화면과 Dynamic Island에서 진행 중인 경기를 따라갑니다.

경기 상세

스코어, 문자중계, 박스스코어, 라인업을 탭으로 나누고 핵심 장면을 골라 봅니다.

기록실

리더보드, 선수 2명 비교, 지표 읽는 법을 제공합니다.

맞춤 알림

결과 중심, 주요 순간, 직접 설정 중에서 받을 알림을 고릅니다.

제가 한 일

  • Flutter 앱과 FastAPI 백엔드를 혼자 개발
  • iOS 위젯과 Live Activity 구현
  • FCM과 APNs 푸시, AWS Lightsail 운영

현재 상태

  • TestFlight 베타(0.1.36)까지 배포했고, 앱스토어 출시는 아직입니다.

구조

앱은 백엔드 API만 바라보고, 경기 정보의 갱신과 보관은 백엔드가 맡습니다.

  1. 클라이언트: Flutter, Riverpod, go_router, SwiftUI 위젯
  2. API: FastAPI, 스케줄러, FCM·APNs 푸시
  3. 데이터: 스냅샷 저장소와 캐시, AWS Lightsail 단일 서버

설계 판단

데이터를 네 종류로 나눠 갱신
실시간, 잠깐 캐시, 보관 스냅샷, 앱 내장 자료로 나눴습니다. 끝난 경기까지 매번 새로 받을 이유가 없어서입니다.
API 실패 시 앱이 원천으로 직접 가지 않기
경로가 둘이면 원인 추적이 어려워집니다. 앱은 마지막 값을 보여 주고 갱신은 백엔드로 일원화했습니다.
적은 비용의 단일 서버부터
테스터 규모에는 Lightsail로 충분하다고 판단하고, ECS/Fargate는 확장 경로로 남겼습니다.

어려웠던 점과 해결

경기 상세에 처음 들어갈 때 응답이 몇 초씩 걸렸습니다.
오래되지 않은 값을 먼저 보여 주고 뒤에서 갱신했으며, 진행 중 경기에 요청이 오면 미리 데워 두게 했습니다.
박스스코어가 늦으면 라인업 응답까지 함께 실패했습니다.
보조 요청을 분리하고 짧은 대기 시간만 주어 서로 영향을 주지 않게 했습니다.

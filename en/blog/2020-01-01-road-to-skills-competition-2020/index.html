The Road to the 2020 National Skills Competition

A chronological record of what I built with DirectX 9, from the shooter I made to apply to the skills team to the 2020 National Skills Competition task.

(Written in 2026, looking back.)

When I entered high school I had no idea where to begin with game development, and my self-introduction said that starting from nothing was very hard. Seoul Digitech High School’s game development skills club made games in DirectX 9 for the game category of the skills competition. The shooting game I made to apply is my oldest surviving record.

A line from that time captures my attitude: be a better me tomorrow than today.

The question

I was doing game jams in Unity, so why was I also writing a framework in DirectX 9? Beyond preparing for competitions, I checked my projects and public code to see what building things myself left behind.

Background and framework

The skills team prepared for competitions where you finish a game within a time limit. With no engine, the work an engine does had to become code, piece by piece. I sorted my projects by which engine feature each one replaced. My sources are the portfolio and public repositories, including two that practiced 2020 national competition problems.

This is Delay from the public practice repository. A wait is just one more function in the queue.

void CScheduleAdmin::Delay(float _fTime)
{
	m_Schedules.emplace(
		[this, _fTime]()->bool {
		m_fTime += udt;
		if (m_fTime > _fTime)
		{
			m_fTime = 0.f;
			return false;
		}
		return true;
	}, _fTime);
}

Reading the code, items run in queue order. Running several effects at the same time needs several queues. Elapsed time accumulates in one member, so it relies on the premise that within a queue the next wait starts only after the previous item ends.

What I tried

Each piece practiced something different. The list’s goal was to behave identically with std:: removed from std::list. Space Of Tank was built in 20 hours in competition format, with map collision judged by pixel color. On learning that DirectX image loading has a maximum size, I split the map into several and scrolled them at random. Under Watch parsed obj and mtl files by hand and used a component-based object structure.

Along the way I also completed a 60-hour DirectX 9 game programming course at Sogang University’s continuing education center and an after-school data structures class.

Where I got stuck and what I changed

The national competition task was to make a casual action game in 20 hours, and I handled everything from design to implementation. Without an engine, every timed effect means handling timers and state variables yourself. So I built Schedule, similar to Unity’s Coroutine, which queues functions and runs them in order.

using Schedule = function<bool()>;

class CScheduleAdmin {
    queue<pair<Schedule, float>> m_Schedules;
public:
    void Add(Schedule _Schedule, float _fDuraction = 0.f);
    void Delay(float _fTime);
    void Update();
};

When a function returns false or the set time passes, it moves to the next item. That greatly cut the time to build timed effects and post-processing.

What I learned

Schedule took Unity’s Coroutine as its reference, and the component structure followed Unity’s scripting structure. I was carrying engine features from game jams into a place without an engine. My self-introduction put it this way: if you keep climbing the road others have built over a long time, the time will eventually come for you to extend it yourself.

That interest in timed flow continued. After joining a company I kept proposing UniTask over Coroutine, a story told in the slot post.

How the practice changed

In time order, the unit of practice shifts. Undersea Jackpot put bullet algorithms such as homing, shotgun, laser, and nWay, along with direction vector math, into one game. Space Of Tank checked eight outer points to judge whether rotation was possible and saved rankings with file I/O. That is practice at shipping something complete with menus and scores within the time limit, as the competition format requires.

Later LinkedList, A*, and BSP map generation were not games but single small algorithms finished in days. Their public repository descriptions also list solo work and the date. I can summarize this as alternating practice on finished games and on parts. In 2020 the practice repositories solving regional problems appear.

Reflection

The change in rank is as the table shows, and how much this practice contributed to going from 5th regionally to 5th nationally cannot be measured. In my interpretation, having tools like Schedule ready before a competition helped under a 20-hour limit. My portfolio also says it saved production time, but there is no number comparing it to working without it.

The counterargument is clear. These days there is rarely a reason to build a game without an engine, and my Schedule falls short of a library like UniTask on exception handling and cancellation points. So I am not recommending that people keep building everything by hand. What stayed with me is less the code than a sense of what costs an engine feature absorbs. That sentence is also my interpretation.

The cover letter line, "be a better me tomorrow than today," describes my attitude. For evidence of skill I used only repositories and competition results.

There is one more limit. The public repositories are practice versions tidied after the competition, so they can’t be treated as the code submitted on site.

General lessons

  • Building part of a tool you use reveals its assumptions.
  • Build tools for time-limited work before the work starts.
  • Write down the premise a homemade tool runs on, such as one wait time per queue.

What came next

In July 2020, the year of the competition, I joined my first company as a high school student.

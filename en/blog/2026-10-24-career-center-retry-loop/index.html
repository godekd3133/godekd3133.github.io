Career Center: Making You Answer the Same Question Again

The rule for picking one question to answer again from mock interview results, and the code that builds the reason sentence only from measured values.

Career Center is a job preparation app connecting job selection through interview review. Comparison reports existed from the MVP, but reports are easy to read and leave. The core loop in the roadmap is mock interview, report, weak-spot map update, and re-asking based on weak spots. So on October 24, 2026 I made retrying the first button on the results, today, and practice screens. Related rules are in packages/core/src/retry.ts.

What I tried

pickRetryAnswer picks one answer using AI evaluations already received.

The answer the AI summary flagged to fixIf none, the lowest sum of content and fitIf no evaluations, the first answer

The threshold for suggesting a retry is the constant RETRY_WEAK_BELOW = 80, and answers where the user pressed “this evaluation is wrong” aren’t suggested.

Where my judgment shifted

If AI makes up why you should retry, it’s hard to trust. So the reason sentence is built from measurements. Below is the code with sentence parts shortened.

export function retryReason(a: AnswerRecord): string {
  const top = fillersCount(a) ? [...a.metrics.fillers].sort((x, y) => y.count - x.count)[0] : undefined;
  if (top && top.count >= 3) return /* "음"이 5번 나왔어요 */;
  if (!a.typed && a.metrics.timeStatus === 'over') return /* 제한 시간 초과 */;
  // 전달력, 내용, 적합도 점수 순으로 확인
  return '';
}

Quotes the AI picks are used only when found in the actual answer through quoteOf, with whitespace removed.

Leaving it to AI

A plausible reason comes out, but its grounds can't be checked.

Now

Sentences come from measured values, and if nothing can be measured it returns an empty string.

speech.ts calculates speech metrics without AI. Browser dictation sometimes removes fillers like “um,” so habits and repeats are counted only for verbatim transcripts. Otherwise wordsMeasured is false and they stay out of the score.

What I learned

The task plan added that same day uses the same principle. The change log says it’s built by rules without AI so no invented numbers get in. As with answering unknown in PC Supporter, not counting what can’t be measured has become a standard I repeat across products.

In virtual customer interviews, responses repeatedly said the score would rise with sharper questions. But these are opinions of personas played by AI, so I treat them only as assumptions.

What’s next

I still don’t know whether this loop actually improves interview skill. Questions were checked with AI virtual personas, and real user validation hasn’t happened. On October 31 I refined the direction toward a job manager connecting cover letter sentences through interviews, and real interviews come next.

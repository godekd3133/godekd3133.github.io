The PC Supporter Rule Engine: Saying "I Don't Know" When It Doesn't

How the compatibility rule engine puts its reasoning and missing information into its results, explained with the actual code and verification results.

PC Supporter is a service that checks the compatibility of a PC build using the Danawa parts catalog. A bare “compatible” or “incompatible” is hard to trust when buying, so I built it so that every judgment comes with its reasoning. The engine lives in shared/domain/engine.ts.

The Shape of a Single Judgment

A rule leaves its result as a finding. It includes the rule ID, severity, affected parts, the facts behind the judgment, and an action the user can take. Severity is split into blocker, warning, info, and unknown.

addUnknown, used when information is missing, puts the missing field in as the fact behind the judgment and attaches an action to check the spec.

The Condition for Passing

A fully compatible verdict only comes out when there are no unknowns either.

function isFullyCompatible(blockerCount: number, warningCount: number, unknownCount: number) {
  return blockerCount === 0 && warningCount === 0 && unknownCount === 0;
}

Without physical values or manufacturer evidence, a result is not promoted to an automatic pass.

What I Filled in with Data

When the engine reports unknowns honestly, empty data means more unknowns. In the October 4 work I fixed the parser and filled in case specs from the manufacturers’ original text.

Case spec Before After
Radiator support by position 0/56 51/56
Supported PSU form factor 51/56 53/56
SSD bays 1/56 56/56

I also put mounting conditions into the judgment. In the verification, a 27mm radiator on the H6 Flow came out as unknown because the rear I/O installation condition couldn’t be confirmed, and a 31mm one came out as a blocker because it exceeds the manufacturer’s 30mm limit.

Remaining Limits

Some cases still have blanks in the table above. The changes haven’t been applied to the production database yet. For the motherboard power delivery rule, the basis for the estimated coefficients was weak, so I changed the judgment approach two days later.

The KBO Fans Widget: Not Hiding Stale Scores

How the Flutter app and the iOS widget exchange data, how update delays are shown, and the widget bugs I fixed, based on the code.

KBO Fans is a baseball app I built to follow my team’s games without opening the app. It began as a class planning document. On March 30, 2026 I added the Flutter app and iOS widget extension, choosing Flutter over the React Native I’d first planned. Serious development with stabilized data began on May 19, and deep links and delay labels followed on May 20.

What I tried

On the Flutter side, WidgetSyncService receives the scoreboard, picks the game to show, and writes values to App Group storage. On the Swift side, WidgetKit only reads and draws them. In the background, a Workmanager task runs the same sync.

Receive scoreboardPick game to showSave to App GroupWidgetKit reads and draws

On iOS one widget draws differently by size: small, medium, large, and three lock screen styles. Android registers a single-game widget and a today’s-games list widget separately.

Where I got stuck and how my judgment changed

An app can’t decide when WidgetKit refreshes, only request it. For a baseball widget, this means an old score can look current. Since the app can’t guarantee refreshes, I decided to say when the score on the widget is from. Text changes after 2 minutes for live games and 15 minutes otherwise.

let ageMs = Int64(Date().timeIntervalSince1970 * 1000) - updatedAtEpoch
let thresholdMs: Int64 = statusKind == "live" ? 2 * 60 * 1000 : 15 * 60 * 1000
if ageMs > thresholdMs {
  return "업데이트 지연 \(updatedAt)"
}
return "업데이트 \(updatedAt)"

For the same reason, I didn’t replace unknown values with other values.

Filling in values

Without pitch data, balls, strikes, and outs would show 0. A game with an empty source score would show 0:0.

Two widget bugs in the CHANGELOG relate to structure.

Symptom Fix
After a brief refresh failure, it wouldn’t refresh again with the same game info Record the comparison signature after widget and Live Activity sync finish
A not-yet-received state showed as a no-game day Separate the two states

The first can happen when a signature meant to skip identical content remembers a failure as if it had succeeded.

What I learned

Here is where I first wrote into code the idea of saying honestly on screen whether a value can be trusted. It’s the same judgment as answering unknown in the PC Supporter rule engine in October 2026. A later app spec also notes that a connection status screen doesn’t mean delivery from the server succeeded.

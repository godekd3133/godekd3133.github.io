Worklog: Solo CEO Staging Deployment

The day I defined the scope of personal data requests and put the staging backend on a single GCP VM. External integrations are stubbed, and the service is unreleased.

Solo CEO is a back-office tool for small business owners, covering government support funds and tax preparation, and it started from a class business plan. On this day I put the staging backend on GCP. It is not a released service yet.

What I Did

I finished the personal data work first.

  • I made it reject personal data requests with an invalid scope.
  • I split exports by scope and made CSV import metrics get reported.
  • I changed the build to lock API dependencies and audit the runtime image.

Then I put the whole staging environment on a single Compute Engine VM.

What’s needed What I used in staging
TLS and entry point Caddy
Queue ElasticMQ (SQS FIFO compatible)
File storage S3-compatible storage
Notifications, business lookup, malware scanning, payment verification Stub servers built with the standard library

What Blocked Me

The production role check failed. The cause was the PostgreSQL initialization script. When I inserted the runtime search_path using the %L string format, all of pg_catalog, public was stored as a single schema name, so current_schemas(false) came back empty. I fixed it to set it as an identifier list.

Decisions

  • I separated the boundaries so the stubs don’t look like real integrations. The malware stub only looks for the EICAR marker, and the business stub only computes a number checksum. Receipt verification always returns verified=false, since there is no real store.
  • I postponed integrating a real payment provider. With the payment backend turned off in the production config, runtime payment attempts are rejected.
  • I decided that pilot notice collection would start with one source, and the rest would be evaluated after the pilot.

What’s Left

Staging is not a release. A real payment provider, store payments, legal review, and external API contracts are still outstanding. The scope also remains the same: it isn’t a service that files on your behalf, and only goes as far as collecting data and exporting it.

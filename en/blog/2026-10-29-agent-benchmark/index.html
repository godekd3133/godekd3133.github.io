How Far Can Agent Results Be Trusted? A Benchmark

I built a benchmark that has agents rebuild released slots and scores the results, and the first thing to doubt was the scorer.

Every time I changed skills or instructions, I had no basis for saying things had improved. So in October 2026 I built a benchmark for slot development agents. The goal isn’t a score of 100. It’s being able to explain in numbers how much scores change, and why, when the model, skills, or instructions change.

How it works

The code of a released slot is rolled back to just before the answer went in, and an agent rebuilds it. Runs happen in a history-free copy with no human input, and the result is compared with the released implementation.

  • Scoring: deterministic checks such as builds, simulation, diffs, and schema comparison come first. The agent’s own progress notes aren’t trusted, and the final state is judged again.
  • Isolation: a running agent is blocked from reading the answer key.
  • Comparison: runs with different conditions are never mixed in the statistics. There’s also a rule that a single score difference doesn’t count as evidence.

The scorer was wrong first

Most of the first problems turned out to be in my tools, not the agents.

  • A path setting was off, so every agent lost a fixed number of points.
  • Some tasks didn’t score near full marks even when grading the answer itself. Part of that was a false positive in path handling.
  • Resource usage was counted lower than it really was.

So I added two checks: grade the answer and see that it scores close to 100, and confirm that the score drops as deliberately planted defects get bigger.

Did the skills help?

I finished one small experiment: a task adding a debug feature, run with and without skills.

Analysis suggested that the skill’s wording may have encouraged failures, but there were too few runs to judge. I also found that the skill document described the answer’s files as if they already existed.

What I still can’t say

I put the main comparison experiment on hold, so I still can’t say how much skills change results. The runtime path has been verified on only one task, and scorer checks on some tasks are still in progress.

There is still a gain from this. I can now say that I don’t have the answer, and show the evidence for it.

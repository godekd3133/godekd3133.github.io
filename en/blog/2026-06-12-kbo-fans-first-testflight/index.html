Worklog: KBO Fans First TestFlight

The day I wrapped up releases 0.0.31 through 0.0.34. I got past a push deployment permission error, but testing on a real device is still outstanding.

This was the first TestFlight release work, after polishing the widget. I include the previous day, June 11, as well.

Context of the day

Ahead of the final presentation, I needed a build testers could use. The app kept its direct data mode and sent only push and Live Activity token registration to the deployed backend. The issue in that day’s records was how far I could call things done.

  • 6.11 Deployed the push backend, solving permission errors one by one
  • 6.12 Releases 0.0.31 through 0.0.34, smoke check with dummy tokens
  • 6.13 Corrected push initialization in 0.0.35 and 0.0.36, added a topic re-registration path
  • 8.31 TestFlight review approved

Where I got stuck

On June 11, CloudFormation deployment kept stopping over permissions. I found and added them one at a time: the service-linked role, ALB security group lookup, ECS role policy lookup, and EFS network interface permissions. To make this easier I first widened failure event logs and output. Finally I fixed an EFS registry lock error.

On June 12 I didn’t get as far as checking on a real device.

Judgment

Deploy permission errorsWiden log scope firstSmoke check with dummy tokensMark device push as incomplete
  • To smoke test before connecting an HTTPS domain, I temporarily added an iOS ATS HTTP exception for that ALB address only. It goes away before final operation.
  • Where no real token was needed, I registered and unregistered dummy tokens and confirmed they were removed afterward.
  • Since I couldn’t check on a device, I didn’t mark push verification as done and listed it as remaining work.

That last item points the same way as later changing the completion condition to execution results.

A breakdown of the permission errors

The permissions blocked on June 11 were of four kinds.

Blocked at What I added
Service-linked role Related permission
ALB Security group lookup
ECS Role policy lookup
EFS Network interface permission

Fixing errors one at a time is slow, but you add what is needed after confirming it from failure events. I widened log range first to learn more from each failure.

Other work that day included fixing an error path when tapping a lineup notification, correcting play-by-play labels, and fixing the data handling description in class presentation slides. The presentation had to state accurately how far the app used the backend. The push fixes in 0.0.35 and 0.0.36 the next day show the unfinished mark that day meant real work remained. The push topic re-registration path was added then too.

The uploaded build carried the backend address for token registration while data stayed in direct mode. I chose to split out the push path first rather than move everything to the backend. I expected game information to keep showing even if the backend had trouble. I didn’t test this under failure, so that effect is my interpretation. Cost and deployment documents added later also show that the backend that day was still a temporary setup.

In short, the day’s results were a successful upload and a server-side smoke pass, while delivery to a real device moved on to the next task. The work log records real-device verification status separately.

Basis for judgment and results

The 0.0.34 record shows static analysis and Flutter tests passing, a successful TestFlight upload, and checks of the version number and embedded patch notes in the archive. It also notes a missing dSYM warning during export.

Check Confirmed Not confirmed
Dummy token smoke Register, unregister, deletion Actual delivery through Apple’s push servers
Upload Build and embedded settings Notification permission flow after install
App tests App code Dynamic Island auto start

This is my interpretation. Finding CloudFormation permissions one at a time seems to have taken long because I had not listed what the first deployment needed. Granting broad permissions from the start would be faster but harder to reduce. I did not compare which was right. The ATS exception was also a temporary trade for convenience, so I marked it as remaining work.

What’s next

Remaining that day: notification permission after TestFlight install, device push, Dynamic Island auto-start, and moving to HTTPS. TestFlight review approval came on August 31.

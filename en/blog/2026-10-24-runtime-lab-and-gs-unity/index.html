Runtime Lab and GS Unity: Verification After the Build Passes

How the verification stage of the workflow uses a runtime replay tool I built and a Unity control tool a colleague built.

Passing code and data checks says nothing about whether the presentation plays correctly on screen. Two tools help close that gap. I built one, and a colleague built the other.

Runtime Lab: what I built

Runtime Lab is a development-only Unity Editor tool. I started it on July 31, 2026 and have kept maintaining it since. On the same day I added a command-line client for agents and a skill for reproducing runtime bugs.

It does three things:

  • Replays recorded server responses to recreate a situation.
  • Judges by rule whether the game state matches what’s expected.
  • Captures a set section frame by frame.

I set boundaries too. Replay only runs when a scenario is explicitly armed, and otherwise the normal path is untouched. Replay results are evidence from the development environment and don’t stand in for checks against the real server, payments, or real devices. Unity can serve only one job at a time, so before changing state, a job first checks whether another one holds it.

GS Unity: what I use and slightly fixed

GS Unity is a Rust CLI that lets agents control the Unity 2022.3 Editor. A colleague built it.

My part is using it, plus one small fix:

  • I wrote the play verification skill’s entry, spin, and state-check procedures around this CLI.
  • I also connected it to the runtime paths of GS App and the benchmark.
  • During cloning, loading a font marked an unsavable sub-asset as modified, and the job was rejected. I excluded only that item from the check and kept rejecting every other change. I found the problem while building a benchmark’s starting state.

How they work together

Play verification now uses GS Unity to operate the Editor and Runtime Lab to recreate situations. On the benchmark’s runtime path, I confirmed actual game entry, spins, and video capture.

In late October, a capture stopped normally but its hold marker stayed in place and blocked another job, so I found and fixed that.

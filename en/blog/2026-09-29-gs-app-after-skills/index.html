GS App: Why I Built an App After the Skills

I designed a desktop app to make skills the entry point for team work, and within a week I had to rethink its screen structure.

GS App is a desktop app that connects game information, AI runs, issue collaboration, simulation, and verification records for slot development in one place. I wrote the design document on July 8, 2026 and started implementing the same day. The design and implementation were mine.

Why an app

The design document targets the whole team: server, client, math, and PMs. Skills are something you call from a terminal after opening a repository, so a person has to work out each time which skill fits which job on which game.

So I made these decisions:

  • A skill launcher, not free chat: people can build only by following the production skills. The task list came from scanning the skill folders, so a new skill would show up in the app.
  • No shared backend: to avoid the burden of running infrastructure, code, metadata, and issues each stayed in their existing systems as the source of truth. When systems disagree, the app doesn’t resolve it. It only shows a warning.
  • Progress display: the app reads the progress files that skills leave behind and shows them as steps.

The review a week later

On July 14 I launched the packaged app and reviewed it screen by screen. The conclusion wasn’t that features were missing. Features had piled up screen by screen, so users had to reassemble their working context every time. Moving to the AI tab dropped the selected game, and the simulation screen offered no way forward when there was no work item to attach.

So I changed direction. Instead of adding tabs, the plan was to connect “prepare, run, verify, hand off” into one work flow, and to move export and diagnostics, which had been separate screens, inside that flow.

What’s left

  • Internal vocabulary: process terms like evidence, gate, and receipt appeared on screen as they were. I later made a separate scorecard for fixing the wording.
  • Write boundaries: external writes go through a preview and a confirmation. AI run permissions are handled separately.
  • Measuring the effect: I haven’t yet measured how much faster the team’s work became.

The app gathered the context, but it didn’t answer whether what got built was correct.

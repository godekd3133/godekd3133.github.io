Mass Delegation: Handing Most of My Work to AI

Around July 2026 I began handing most of my work to AI, and missed verification led me to change the completion condition.

(Written in 2026, looking back.)

After moving procedures into skills, around July 2026 I began delegating work broadly to AI. This was also when I started building in-house AI tools to support slot development.

Why I started

I wanted to delegate work beyond coding tools. From June I tested AgentB, a personal agent in Slack, trying skills, session handoff, calls, and local model routing in turn. The biggest limit was the platform: inside Slack it only moved when tagged.

What I tried

I split work across many sessions, and in August began using automatic review and hooks. Time spent dividing work and checking results grew beyond time spent typing code. I also split models by stage to save usage. The super bonus case I shared with the team in September looked like this.

Stage What was delegated
Server Structure design in plan mode, development and simulation in goal mode
Client Structure design, correction to stay within our existing work style
Flow Sequence-focused and presentation-focused work on different models

Where I got stuck and what I changed

Delegating more meant verification after changes was often skipped: the agent reported done without actually running anything. So I changed the completion condition from the agent’s report to actual execution results.

Before

When the agent writes done, move to the next stage.

After

Done requires the commands run and their results, with how far each layer was checked written separately.

In August I gathered my feedback for a retrospective. Instead of treating all follow-up fixes as agent mistakes, I sorted them into direct misunderstanding, spec change, defect first appearing at runtime, and incomplete evidence. This sorting continues in the post on reorganizing skills.

With AgentB in July I tested a tool for placing phone calls and routing a local model to Codex. The table’s extra correction step against our existing work style, after client structure design, turned my March coding style feedback into procedure.

I used the same approach in in-house game jams. In the February-March 2026 AI jam I built a minigame hub, core systems, and agent work rules, and in the July-September new game exploration I built several candidates, compared them, and focused on one.

What I learned

The more I delegated, the more my work shifted from typing code to dividing and checking. And for the team to use AI tools, there had to be an entry point outside the terminal.

What’s next

That entry point became GS App. How to trust execution results led to Runtime Lab and the benchmark.

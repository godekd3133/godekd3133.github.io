R&D

Adopting UniTask across the team

Why it was needed
Coroutine-based feature code made flying and presentation waits cumbersome, and hangs or missed cleanups were hard to check.
What I did
I kept proposing UniTask after joining and shared examples. A colleague handled the common foundation; I applied it to new slots and added review checklist items.
Effect
The team decided to use UniTask from the next slot on, and flying and presentation wait code became simpler.

Moving from visual scripting to scripts

Why it was needed
NodeCanvas graphs ended up used mostly by developers, unlike the original intent, and graphs are hard to review, diff, test, and analyze with AI.
What I did
I refactored symbol behavior into scripts, pushed feature logic into UniTask-based script controllers, and started converting FSMs to code in 2026.
Effect
Writing new features as script controllers became the norm. Some FSM and BT flows remain, so the shift is ongoing.

ReelV2 reel system

Why it was needed
Reel performance problems kept recurring in slot development.
What I did
I proposed a new reel system with a different pooling approach from 2022, joined early implementation, and improved it on real slots. A colleague led main development.
Effect
Performance issues stabilized and it helped optimize slots using spot reels.

Grand Ways reel system

Why it was needed
There was no way to build a slot where every reel could change size.
What I did
I built a variable-size reel system for Fist of Zeus, and later a single-call way to switch reel movement modes.
Effect
It shipped live in Fist of Zeus, and the switching feature was also used in a Golden Drums super bonus.

Jackpot board optimization and bitmap font importer

Why it was needed
Jackpot board display had become a performance burden.
What I did
I proposed bitmap fonts and built an importer to bring them in easily.
Effect
This resolved the jackpot board performance issue.

Tools I built and used

Unity Bridge

Why it was needed
When an AI agent edited game-flow files as plain text, Unity assets could easily break, so it needed a safe way to work inside the editor.
What I did
I didn't build this tool; I applied a bridge made in-house to slot development. I used it on a Super Bonus feature in February 2026 and in March bundled common calls into a reusable skill.
Effect
The agent could move from editing asset files directly to changing game flows through the tool. No measured impact was recorded.

AI Bug Reporter

Why it was needed
When an error occurred in Unity, the cause was hard to trace or hand off as an issue unless the screen and game state from that moment were kept.
What I did
I built an editor tool that automatically saves the screen, video, logs, object hierarchy, and server responses at the moment of an error. It produces a report for people and an evidence package for AI, and can hand off to Jira.
Effect
People and AI can now review the same evidence from the moment of an error and pass it on as an issue.

Runtime Lab

Why it was needed
Reproducing a specific spin result or complex situation in Unity meant playing by hand until the right conditions appeared.
What I did
I built a development-only tool that replays recorded server responses to run a chosen spin scenario right away and check the outcome alongside the screen. It can also be run from the command line.
Effect
The same conditions can be reproduced repeatedly, and AI agents can run the same scenarios. In October 2026, the team revisited whether to keep maintaining it.

GS Unity CLI

Why it was needed
I raised with the team whether the existing bridge was truly practical for daily work and, if not, how to make it so.
What I did
A colleague led the CLI's development. I raised the practical-use discussion, asked for its work to be tracked over time, and contributed one fix for an asset-copy error.
Effect
According to my colleague's records, agents can enter Play Mode, enter a game, spin, and trigger debug spins on their own, and the team decided to try it in a slot jam.

What I owned

  • Handled the desktop app's design, main process, screens, and releases on my own.
  • Built a slot development workflow for AI agents.
  • Built a benchmark that evaluates agents by having them reimplement shipped slots.

Scope

I developed the desktop app on my own.

Building and verifying math with designers

Situation
As super bonuses increased, math design, revision, and verification had to repeat quickly, and designers' change requests needed checking against real server results.
What I did
With AI agents I analyzed specs to produce math models and documents and verified them with real server simulation. I also built a tool to run designer adjustments through the simulator and compare them, and a desktop app to select and run simulations.
Outcome
Math, server, and client ran as one flow, and designer change requests could be confirmed by simulation before reaching the server. Final approval of live math stays with design review.

Sorting QA Bug Tickets by Root Cause

Situation
QA on a bonus feature left me with several assigned bug tickets at once, mixing wrong-looking amounts with presentation glitches.
What I did
For each ticket I first separated bad server values from bad on-screen display, fixed the display bugs, and wrote the cause, fix, and result on the ticket so QA could read it directly.
Outcome
Fixed tickets were source-checked and built, with on-screen confirmation tracked as a separate open item. One skip-animation ticket was recorded as investigation only.

Closing Gaps Between Server Responses and the Response Schema

Situation
Fields in the server result kept going missing from the Schema files, and in some cases the server sent a different value, so settings never reached the client.
What I did
I set a working order that treats the server response, Schema.json, Schema.txt, and client display as one unit, starting with the server.
Outcome
This check became the definition of done for later changes to the server-client response format.

Reproducing and Fixing a Board vs. Result Popup Mismatch

Situation
A QA ticket reporting that the amounts on the board did not add up to the result popup was reopened after a fix.
What I did
I worked through the server response and confirmed the total was right while the board display lagged behind. With an AI agent, I built a repro path that forces the same response to replay, then fixed the display side.
Outcome
In the forced repro, the board total matched the popup, and the fix passed review and QA.

Tracing a Screen Mismatch After a Reel Config Change

Situation
After I adjusted the bonus reel configuration, the game screen looked out of step with the new settings.
What I did
I compared the source values with the generated file the server actually reads, found old values left in the generated file, and regenerated it.
Outcome
Source and generated values matched and the server response test passed. The regeneration requirement was written into the docs.

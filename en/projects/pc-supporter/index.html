PC SupporterAI

A PC build assistant that shows the reasoning behind whether your parts are compatible

Live beta, Service, Sep 2026 ~ ongoing

OpenOpen GitHub repository

The problem

A plain yes or no on part compatibility is hard to trust when you're about to buy. I built a tool that shows both the reasoning behind each decision and where the data comes from.

For first-time PC builders who want to see the reasoning before trusting a parts list.

Key features

Compatibility with reasons

Each result shows which specs were compared, not only pass or fail.

Start with one sentence

Type something like "QHD gaming, 2.2M KRW, 32GB RAM" and the app lays it out as editable conditions, with chips for what is missing.

Data trust labels

Price checks, missing specs and benchmark sources appear next to each part.

Pre-purchase check

Compatibility issues, a checklist, price changes and build records sit on one screen.

Post-build temperature logs

Import HWiNFO or OCCT sensor CSVs and compare runs under the same load.

What I did

  • Checked compatibility with a rule engine that explains its reasoning
  • Generated builds automatically from a one-line request
  • Implemented price tracking and a flow for recording build evidence
  • Wrapped the web service with Capacitor to ship it as a mobile app

Current status

  • Starter catalog of 115 core parts, plus 42 peripheral parts in 10 categories

Architecture

Web and server share the compatibility code, and Capacitor wraps the same web app for mobile.

  1. Client: React, Vite, Capacitor (iOS, Android)
  2. API: Express with compatibility and recommendation engines in shared/domain
  3. Data: PostgreSQL, public product listings and a starter catalog (115 core parts, 42 accessories)

Design decisions

Separate compatibility, data trust and real build results
This is the core rule in the development doc. Whether parts fit and whether the data behind that verdict is reliable are different questions, so they never merge into one score.
Recommendations stop at candidates and comparison
Auto-applying a risky candidate would hide the reasoning, so users preview and choose.
Rule-based parsing of requests
The same sentence must always produce the same conditions. The parsed result is shown so it can be corrected right away.

Challenges and solutions

A stalled request on mobile left the screen loading forever.
Each request attempt now has a timeout and a retry, so the app recovers from stalled calls.
Sensor CSVs differ in column names across tools and can have gaps.
Columns are mapped automatically with a preview before applying, gaps and bad values appear on a quality card, and time series are compressed to at most 240 points.

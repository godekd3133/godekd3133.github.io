Rune Breaker: The Wizard's Dungeon

A 3D top-down hack-and-slash roguelite that runs in the browser

Playable demo, Game, Through Oct 2026 (including work before the repository move)

Play

The problem

Balancing a game you make on your own tends to come down to gut feel. So I built a tool alongside it for changing values right away.

For players who want a quick 3D action roguelite in the browser with nothing to install.

Key features

Room-by-room dungeon combat

Clear rooms, pick blessings and work up to the boss at the end of each floor.

Distinct boss attacks

Bosses have their own patterns plus dedicated third-phase finales and signature attacks.

Multiple modes

Beyond expeditions there are Endless Battlefield, daily dungeons and giant boss hunts.

Long-term growth

Gear enhancement and refinement, runes and a hero stat sheet carry progress between runs.

PC and mobile controls

Keyboard, mouse and touch are all supported, with adjustable button size and opacity.

What I did

  • Built toon-shaded 3D combat with Three.js
  • Created a separate balance console and balance service for tuning values
  • Created dedicated finales for 12 bosses and 24 new unique attacks
  • Collected about 170 findings across 8 areas and applied them starting with the highest-priority groups

Current status

  • Solo development using AI agents, continuing work moved over from v19~20

Architecture

The game is a static web app, while balance values are edited in a separate console and service and then loaded by the game.

  1. Client: Three.js, Vite, native app build project
  2. API: balance service and an owner-only balance console
  3. Data: database managed with drizzle, sheet integration and local saves

Design decisions

Keep balance tools apart from the game
Editing code for each number change is slow. The console shows simulations and curves so tuning can be applied directly.
Build boss and hero models through Blender
Models assembled from primitives hit a clear quality limit, so the project standardized on GLB output from tools/blender.
One registration point for content
Extension files import existing files and never the reverse, which prevents circular imports from breaking initialization.

Challenges and solutions

When a hit-reaction effect cleared bullets, the bullet loop crashed.
The loop now guards its length and removes by object, and a reproduction script stays in the project.
In wide rooms the camera could push the character under on-screen buttons.
Per-device safe zones keep the character inside the visible play area.

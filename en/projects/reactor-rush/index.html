Reactor Rush

A 3D action expedition game where you catch enemy bullets and fire them back

Playable demo, Game, 2026

Play

Opens in a new page. Some images were generated with AI.

The problem

When the core mechanic is catching and returning bullets instead of just dodging them, the feel of the input is everything. I refined it so it feels the same on PC, on touch, and in portrait mode.

For players who want a short, responsive 3D action game on touch or with keyboard and mouse.

Key features

Capture and return fire

Open a field, gather up to 12 enemy shots and press again to send them back.

Perfect dodge

Dodging just before a hit charges your ultimate and shortens cooldowns.

Readable boss fights

Barrages, slams and charges are marked on the floor, with an opening to counter afterward.

Evolutions and routes

Pick an evolution and the next battle route between zones, so each run plays differently.

Unlocks and rematches

First clears award weapons and outfits and open boss rematches with per-build records.

What I did

  • Designed the controls for capturing and reflecting enemy bullets
  • Supported both PC and touch input
  • Refined the portrait-mode UX

Architecture

A single-player game that runs in the browser with no server. Attack, route and weapon rules live in small modules.

  1. Client: Three.js, TypeScript, Vite
  2. API: none (static build)
  3. Data: campaign records in browser storage

Design decisions

Hold input until the shot fires
A quick tap lost to a cooldown feels like a dropped input, so firing intent is stored until a volley accepts it.
Focus first controls on moving and capturing
Asking new players to aim too keeps them from the core idea, so auto-fire starts on and the largest button is capture.
Rules as shared data contracts
UI and combat read the same rule modules, so descriptions stay in line with actual behavior.

Challenges and solutions

In portrait mode, enemies could drift off camera and become hard to find.
An edge marker points to only the nearest off-screen enemy, giving direction without covering the fight.
Warning markers could steal taps meant for choosing a target.
Picking now tests real models only, so the nearest visible enemy wins.

What is next

  • Test input and performance on real phones
  • Refine combat and reward flow with player feedback

It started as a core-stealing game called Spark Raid. I judged it lacking and rebuilt it several times, then shifted to its current form: Reactor Rush, a single-player 3D action expedition.

협업과 라이브 대응 사례

이 작업들은 대부분 AI 에이전트와 함께 진행했고, 원인 판단과 최종 확인은 제가 했습니다.

QA 버그 티켓을 원인별로 나눠 함께 해결

상황
보너스 기능 QA에서 제가 담당한 버그 티켓 여러 건이 한꺼번에 열렸고, 금액이 다르게 보이거나 연출이 어긋나는 증상이 섞여 있었습니다.
한 일
티켓마다 서버 값이 틀린 것인지 화면 표시가 틀린 것인지 먼저 가린 뒤 표시 오류를 고쳤고, QA가 바로 읽을 수 있게 원인, 수정, 결과를 나눠 티켓에 남겼습니다.
결과
수정한 티켓은 코드 확인과 빌드까지 마쳤고, 실제 화면 확인은 남은 항목으로 분리했습니다. 스킵 연출 티켓은 원인 조사까지만 진행했다고 기록했습니다.

서버 응답과 Response Schema의 어긋남 정리

상황
서버 결과에는 있는 필드가 Schema 파일에 빠져 있거나, 서버가 다른 값을 내려주어 설정이 클라이언트까지 닿지 않는 일이 반복됐습니다.
한 일
서버 응답, Schema.json, Schema.txt, 클라이언트 표시를 하나의 묶음으로 보고 서버부터 순서대로 고치도록 작업 방식을 정했습니다.
결과
이 점검 순서가 이후 서버와 클라이언트 응답 형식을 바꿀 때의 완료 기준이 됐습니다.

보드 금액과 결과 팝업 차이 재현과 수정

상황
보드에 보이는 금액의 합과 결과 팝업의 금액이 다르다는 QA 티켓이 수정 후 다시 열렸습니다.
한 일
서버 응답을 직접 계산해 총액은 맞고 보드의 표시 값이 따라가지 못한다는 점을 확인했습니다. AI 에이전트와 함께 같은 응답을 강제로 재생하는 재현 경로를 만들어 표시 쪽을 고쳤습니다.
결과
강제 재현에서 보드 합계와 팝업 금액이 일치하는 것을 확인했고, 리뷰를 거쳐 QA를 통과했습니다.

릴 설정 조정 후 화면 불일치 원인 찾기

상황
보너스 릴 설정을 조정한 뒤 게임 화면이 새 설정과 맞지 않아 보이는 문제가 있었습니다.
한 일
소스의 값과 서버가 실제로 읽는 생성 파일을 비교해, 생성 파일에 이전 값이 남아 있는 것을 찾아 다시 생성했습니다.
결과
소스와 생성 파일의 값이 일치했고 서버 응답 테스트도 통과했습니다. 다시 생성해야 한다는 조건은 문서에 남겼습니다.
